# 观止东方 · 合作联系表单字段草案

> 版本: v0.1-draft | 日期: 2026-08-09

---

## 一、设计原则

1. **低摩擦** — 字段越少转化率越高，只拿真正需要的信息
2. **品牌调性** — 表单视觉与编辑式美学一致，不突兀
3. **渐进式** — 核心字段在前，选填在后，不吓跑人
4. **先缓后紧** — 初期用轻量邮件通知，后续接入后台 CRM

---

## 二、字段清单

### 2.1 必填字段（4 项）

| # | 字段 | 类型 | 占位提示 | 校验 | 说明 |
|---|------|------|----------|------|------|
| 1 | **姓名** | text | "您的姓名" | 2-20 字 | |
| 2 | **机构名称** | text | "您所在的机构或公司" | 2-50 字 | B2B 场景必须知道对方是谁 |
| 3 | **联系邮箱** | email | "example@domain.com" | RFC 5322 | 主要回复渠道 |
| 4 | **合作意向** | select | "请选择合作方向" | 必选 | 帮助快速分流线索 |

> **为什么只有 4 个必填项？** 每多一个必填字段，转化率下降约 10%。核心信息够了就先提交，其余可以后续沟通中补全。

### 2.2 选填字段（3 项）

| # | 字段 | 类型 | 占位提示 | 说明 |
|---|------|------|----------|------|
| 5 | **手机 / 微信** | tel | "方便我们与您联系" | 国内 B2B 场景微信沟通很常见 |
| 6 | **职位** | text | "您的职务" | 帮助判断对方决策权限 |
| 7 | **留言** | textarea | "请简述您的合作需求或关注的文化母题…" | 开放输入，捕捉额外信息 |

### 2.3 隐藏字段（自动采集）

| 字段 | 来源 | 说明 |
|------|------|------|
| 来源页面 | `document.referrer` / URL query | 知道对方从哪个渠道来的 |
| 提交时间 | `new Date().toISOString()` | 服务端也记一份 |
| 语言 | `navigator.language` | 后期英文版时有用 |

## 六、校验规则

### 6.1 实时校验（onBlur）

| 字段 | 规则 | 错误提示 |
|------|------|----------|
| 姓名 | 2-20 个字符，不能纯数字 | "请输入 2-20 个字符" |
| 机构名称 | 2-50 个字符 | "请输入机构或公司名称" |
| 联系邮箱 | 合法邮箱格式 | "请输入有效的邮箱地址" |
| 手机/微信 | 选填；若填则 6-20 位数字或含 `-_+` | "请输入有效的联系方式" |
| 职位 | 选填；若填则 ≤30 字符 | "请输入 30 个字符以内" |
| 合作意向 | 必选 | "请选择合作方向" |
| 留言 | 选填；若填则 ≤500 字符 | "留言请控制在 500 字以内" |

### 6.2 提交校验

- 所有必填字段非空 + 格式正确才允许提交
- 提交中按钮禁用并显示 loading，防止重复提交
- Honeypot 字段（隐藏的 input，仅机器人会填）— 防垃圾

## 八、防垃圾策略

| 策略 | 说明 |
|------|------|
| **Honeypot** | 隐藏 input，用户不可见，机器人自动填写 → 直接拒绝 |
| **提交间隔** | 同 IP / 同邮箱 60 秒内只能提交一次 |
| **速率限制** | 单 IP 每小时最多 5 次提交 |
| **Turnstile** | CF Turnstile 免费人机验证（可选，初期不加） |

## 十、技术实现要点

### 10.1 前端（Contact 组件改造）

```typescript
// Contact.tsx 新增 ContactForm 子组件
// src/components/ContactForm.tsx

interface FormData {
  name: string;
  org: string;
  email: string;
  phone: string;
  title: string;
  intent: string;
  message: string;
}

// 表单状态机
type FormState = 'idle' | 'submitting' | 'success' | 'error';

// 提交
const onSubmit = async (data: FormData) => {
  setState('submitting');
  try {
    const res = await fetch('/api/leads', {
      method: 'POST',
      headers: { 'Content-Type': 'application/json' },
      body: JSON.stringify(data),
    });
    if (!res.ok) throw new Error();
    setState('success');
  } catch {
    setState('error');
  }
};
```

### 10.2 后端（CF Workers）

```
POST /api/leads
  → 校验 + honeypot 检查 + 速率限制
  → 写入 D1 leads 表
  → 发送邮件通知
  → 返回 { ok: true }
```

### 10.3 依赖

```json
{
  "dependencies": {
    "hono": "^4.x",           // Workers 路由框架
    "zod": "^3.x",            // 表单校验（前后端共用 schema）
    "resend": "^4.x"          // 邮件发送
  }
}
```

## 十一、总结

| 维度 | 设计决策 |
|------|----------|
| 必填字段 | 4 个（姓名、机构、邮箱、意向）— 最小摩擦 |
| 选填字段 | 3 个（微信、职位、留言） |
| 下拉选项 | 7 项，对齐已有合作模式 |
| 视觉 | 编辑式美学 — 宣纸底、墨字、朱砂 accent、直角输入框 |
| 校验 | 实时 blur 校验 + 提交前置校验 |
| 反垃圾 | Honeypot + 速率限制（2 层） |
| 成功态 | 感谢语 + 微信二维码，引导即时联系 |
| 失败态 | 错误提示 + 邮件兜底 + 重试按钮 |
| 通知 | 提交成功 → 邮件通知管理员（Resend） |
| 移动端 | 单列布局，完整支持 |
